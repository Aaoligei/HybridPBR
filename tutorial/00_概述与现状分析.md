## 第一章：概述与现状分析

### 1.1 为什么需要降噪和抗锯齿？

想象一下，你用一台老式相机拍摄夜景照片——照片上会出现很多噪点，这是因为光线不足，相机感光元件收到的光子太少，产生随机波动。光线追踪渲染器面临同样的问题：

```
┌─────────────────────────────────────────────────────────────┐
│                    光线追踪的噪声来源                        │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│   现实世界              光线追踪模拟                         │
│   ──────────           ──────────────                       │
│   无限光子              有限光线样本                         │
│   自然平均              蒙特卡洛估计                         │
│   无噪声                产生方差（噪声）                     │
│                                                             │
│   ┌──────────┐         ┌──────────┐                         │
│   │  平滑的  │   vs    │  噪点的  │                         │
│   │  渐变    │         │  斑驳    │                         │
│   └──────────┘         └──────────┘                         │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

**降噪**的目标：用尽可能少的样本，得到尽可能干净的图像
**抗锯齿**的目标：让物体边缘平滑，避免"锯齿状"的走样

### 1.2 当前实现概述

#### 1.2.1 降噪系统现状

当前项目使用的是**简单的双边滤波器**（Bilateral Filter），位于：
- `src/rendering/raytracing/Denoiser.h/cpp`
- `assets/shaders/compute/denoiser.comp`

**工作原理简图**：

```
输入噪声图像                双边滤波处理               输出降噪图像
┌─────────────┐         ┌─────────────┐         ┌─────────────┐
│ ▓▓░░▓▓░░▓▓ │         │  对于每个像素  │         │ ▓▓▓▓░░▓▓▓▓ │
│ ░░▓▓░░▓▓░░ │   ──►   │  根据颜色相似度 │  ──►   │ ░░▓▓▓▓░░░░ │
│ ▓▓░░▓▓░░▓▓ │         │  加权平均邻域  │         │ ▓▓▓▓░░▓▓▓▓ │
└─────────────┘         └─────────────┘         └─────────────┘
```

**核心代码片段**（`denoiser.comp`）：

```glsl
// 遍历9x9邻域
for (int y = -KERNEL_RADIUS; y <= KERNEL_RADIUS; y++) {
    for (int x = -KERNEL_RADIUS; x <= KERNEL_RADIUS; x++) {
        // 空间权重：距离越远，权重越小
        float weightSpatial = exp(-dist2 / (2.0 * SIGMA_SPATIAL * SIGMA_SPATIAL));
        
        // 颜色权重：颜色差异越大，权重越小
        float weightColor = exp(-colorDist2 / (2.0 * sigmaColor * sigmaColor));
        
        float weight = weightSpatial * weightColor;
        sumColor += sampleColor * weight;
        sumWeight += weight;
    }
}
```

#### 1.2.2 抗锯齿系统现状

当前项目使用**简单的时域累积 + 随机抖动**，位于：
- `assets/shaders/compute/ray_generation.comp`（光线生成）
- `assets/shaders/compute/path_tracing.comp`（帧累积）

**工作原理**：

```
帧 1: 像素中心采样      帧 2: 随机偏移采样      累积结果
      ┌───┐                  ┌───┐
      │ • │                  │•  │           多帧平均
      └───┘                  └───┘      ──►  减少噪声
   (标准位置)            (随机偏移)
```

**核心代码片段**（`ray_generation.comp`）：

```glsl
// 添加随机偏移用于抗锯齿
if (frameNumber > 0) {
    vec2 jitter = vec2(
        float((pixelIndex * 1973 + frameNumber) & 0xFF) / 255.0 - 0.5,
        float((pixelIndex * 9277 + frameNumber) & 0xFF) / 255.0 - 0.5
    ) / float(width);
    uv += jitter;
}
```

**帧累积代码**（`path_tracing.comp`）：

```glsl
// 混合历史帧
if (frameNumber > 0) {
    vec3 history = accumulationPixels[pixelIndex].rgb;
    float weight = 1.0 / float(frameNumber + 1);
    color = mix(history, color, weight);  // 简单线性混合
}
```

### 1.3 当前实现的局限性分析

#### 1.3.1 降噪系统的局限性

| 问题类别 | 具体问题 | 视觉表现 | 严重程度 |
|---------|---------|---------|---------|
| **几何信息缺失** | 不使用深度、法线信息 | 边缘模糊，特征丢失 | ⭐⭐⭐⭐⭐ |
| **时域不稳定** | 无时间一致性保证 | 画面闪烁 | ⭐⭐⭐⭐⭐ |
| **单一尺度** | 只用一个滤波核大小 | 大尺度噪声残留 | ⭐⭐⭐⭐ |
| **颜色空间** | 直接在RGB处理 | 颜色偏移 | ⭐⭐⭐ |
| **参数固定** | 无法适应不同噪声水平 | 过度模糊或降噪不足 | ⭐⭐⭐ |

**详细分析**：

```
问题1: 缺少几何特征引导
═══════════════════════════

当前做法：
┌─────────────────────────────────────────┐
│  像素A (红色墙面)    像素B (绿色物体)   │
│       ████               ████           │
│       ██████  ← 边界 →  ██████          │
│                                         │
│  颜色差异很大 → 权重很低 → 边缘保留 ✓    │
│                                         │
│  但是！如果噪声很大：                    │
│  像素A的噪声使其接近像素B的颜色          │
│  → 权重变高 → 边缘模糊 ✗                │
└─────────────────────────────────────────┘

理想做法（使用G-Buffer）：
┌─────────────────────────────────────────┐
│  法线/深度信息告诉我们：                 │
│  "这里是个边缘，即使颜色相似也要保留"    │
│                                         │
│  ┌────────┐  ┌────────┐                 │
│  │ 法线   │  │ 深度   │                 │
│  │ ─────  │  │ ─────  │                 │
│  │ 相同→  │  │ 不同→  │                 │
│  │ 可以   │  │ 保留   │                 │
│  │ 模糊   │  │ 边缘   │                 │
│  └────────┘  └────────┘                 │
└─────────────────────────────────────────┘
```

```
问题2: 时域不稳定
════════════════════

当前帧：随机噪声分布
历史帧：不同的随机噪声分布

简单的线性混合：
  result = history * (1 - weight) + current * weight

问题：
  - 噪声模式在帧间随机变化
  - 混合后仍有闪烁
  - 没有检测"历史是否有效"

例子：
  帧1: 像素值 = 0.8 (噪声导致偏高)
  帧2: 像素值 = 0.5 (噪声导致偏低)
  混合: 结果在0.5-0.8之间跳动 → 闪烁！
```

#### 1.3.2 抗锯齿系统的局限性

| 问题类别 | 具体问题 | 视觉表现 | 严重程度 |
|---------|---------|---------|---------|
| **随机数质量低** | 简单哈希，模式重复 | 残留规律性噪声 | ⭐⭐⭐⭐ |
| **无运动向量** | 不追踪像素运动 | 运动物体拖影 | ⭐⭐⭐⭐⭐ |
| **采样分布差** | 非均匀分布 | 收敛慢 | ⭐⭐⭐⭐ |
| **累积策略简单** | 等权重平均 | 难以处理变化 | ⭐⭐⭐ |

**详细分析**：

```
问题3: 随机数质量问题
═════════════════════

当前代码使用的随机数生成：
seed = pixelIndex * 1973 + frameNumber * 26699

问题：
┌─────────────────────────────────────────┐
│  这是一个"线性同余"风格的简单哈希       │
│                                         │
│  优点：计算快                           │
│  缺点：                                 │
│  - 周期性模式（每过一段时间会重复）      │
│  - 高维投影不均匀                       │
│  - 像素间的"随机性"不够独立             │
└─────────────────────────────────────────┘

对比低差异序列：
┌─────────────────────────────────────────┐
│  Sobol/Halton序列：                     │
│  - 确定性（相同输入总是相同输出）        │
│  - 更均匀的分布                         │
│  - 更快的收敛速度                       │
│                                         │
│  想象在像素内采样：                     │
│  随机采样：可能聚集在某处                │
│  Sobol：均匀覆盖整个像素区域            │
└─────────────────────────────────────────┘
```

```
问题4: 缺少运动向量
════════════════════

场景：一个球从左向右移动

帧1: 球在位置A
帧2: 球在位置B（移动了）

时域累积的问题：
┌─────────────────────────────────────────┐
│  当前实现：                              │
│  - 像素(100,100)在帧1是球的颜色         │
│  - 像素(100,100)在帧2是背景颜色         │
│  - 简单混合 → 出现"鬼影"                │
│                                         │
│  正确做法（使用运动向量）：              │
│  - 找出帧2的像素(100,100)对应帧1的哪个位置 │
│  - 假设运动向量显示"来自(90,100)"       │
│  - 从帧1的(90,100)采样历史              │
│  - 这样就正确追踪了运动                 │
└─────────────────────────────────────────┘
```

### 1.5 预备知识

在开始改进之前，请确保你了解：

#### 必要概念

1. **蒙特卡洛积分**
   - 路径追踪本质上是在用随机采样估算积分
   - 样本越多，结果越精确（但越慢）

2. **G-Buffer（几何缓冲区）**
   - 延迟渲染中存储场景几何信息的纹理
   - 包含：位置、法线、深度、材质ID等

3. **计算着色器（Compute Shader）**
   - 本项目的降噪和光线追踪都在计算着色器中执行
   - 理解workgroup、local invocation等概念

#### 项目中的关键文件

```
你需要修改/创建的文件：

降噪相关：
├── src/rendering/raytracing/Denoiser.h/cpp     # C++降噪类
├── assets/shaders/compute/denoiser.comp        # 当前降噪着色器
└── assets/shaders/compute/denoiser_atrous.comp # 新建：A-Trous滤波器

抗锯齿相关：
├── assets/shaders/compute/ray_generation.comp  # 光线生成着色器
├── assets/shaders/compute/path_tracing.comp    # 路径追踪着色器
└── src/rendering/raytracing/TAAResolver.h/cpp  # 新建：TAA解析器

辅助文件：
├── src/rendering/raytracing/SobolSequence.h    # 新建：Sobol序列
└── assets/shaders/compute/motion_vectors.comp  # 新建：运动向量计算
```

### 1.6 小结

本章我们分析了当前HybridPBR项目中降噪和抗锯齿系统的实现，发现了以下核心问题：

1. **降噪**：缺少几何引导、时域不稳定、单一尺度
2. **抗锯齿**：随机数质量低、缺少运动向量、采样策略简单

接下来的教程将逐步解决这些问题。建议按顺序阅读和实践，每个阶段完成后都会有可见的改进效果。
